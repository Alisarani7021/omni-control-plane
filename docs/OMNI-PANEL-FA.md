# نود OMNI و کنترل‌پلین V13

## مدل
نود OMNI یک Worker **هدلس** روی اکانت خودِ تنانت است: API + تونل VLESS + D1 + DO + کرون.
بدون UI و بدون VPS. رابط کاربریِ تنانت **همین ربات/کنترل‌پلین** است و از راه
کانال عامل با نود حرف می‌زند.

### قرارداد هدر کانال عامل (مهم)
نود یک **آرتیفکت پین‌شده** در حساب خودِ کاربر است؛ تغییر نام هدر در کنترل‌پلین
هیچ‌وقت باندل‌های نصب‌شده در حساب کاربران را عوض نمی‌کند. بعد از تغییر برند
کاوه→OMNI هدر خروجی به `X-Omni-Agent` تغییر کرد ولی
`omni-panel/dist-headless/omni-headless.js` هنوز `x-kaveh-agent` را می‌خواند و
نتیجه‌اش این بود که هر تماس عامل با `403 «کلید عامل نامعتبر است»` برمی‌گشت:
رمز مدیر ست نمی‌شد، لیست/ساخت کاربر خطا می‌داد و کاربر VIP خودکار هم بی‌صدا
رهاش می‌شد. الان `omniAgent()` **هر دو هدر** را می‌فرستد:

- `X-Omni-Agent` — نام امروز
- `X-Kaveh-Agent` — همان چیزی که باندل پین‌شده می‌خواند

تست `tests/omni-agent-contract.test.ts` این قرارداد را قفل می‌کند: نام هدر را از
داخل خودِ باندل پین‌شده استخراج می‌کند و اگر کنترل‌پلین دیگر آن هدر را نفرستد،
تست fail می‌شود. با هر `sync-omni-panel --rebuild` که باندل را دوباره pin کند
می‌توان این ناسازگاری را تمیز کرد.

### پنل وب نود
باندل هدلس `[assets]` ندارد و هر مسیر غیر API در نود `404` است؛ یعنی
`<base>/panel` روی این نودها وجود ندارد و ربات هم دیگر به آن لینک نمی‌دهد.
مدیریت (کاربر، اشتراک، مصرف) در خود ربات است و «🔑 رمز مدیر نود» رمز مدیر خودِ
نود است (برای API/ابزار مالک)، نه ورود به یک پنل وب.

## اجزا
- `src/omni-source.ts` — باندل هدلسِ نود، **درون همین ریپو** (`omni-panel/dist-headless/`)
  و پین‌شده با sha256؛ `scripts/sync-omni-panel.mjs` آن را در `src/omni-source.ts`
  جاسازی می‌کند و هیچ fetch زمان‌اجرا وجود ندارد. بازسازی اختیاری:
  `node scripts/sync-omni-panel.mjs --rebuild`.
- `src/omni-engine.ts` — ساخت D1 (idempotent)، آپلود Worker با بایندینگ‌های
  D1/DO/سکرت‌ها، فعال‌سازی workers.dev، حذف، و کلاینت کانال عامل.
- `src/omni-flows.ts` — فلوهای ربات: ساخت نود + کاربر VIP، لیست کاربران،
  کاربر سریع، بازیابی رمز، حذف نود. کلید عامل مثل توکن اتصال‌ها با AES-GCM و AAD اختصاصی رمز می‌شود.
- `migrations/0005_kaveh_nodes.sql` — جدول نودها (نام جدول برای سازگاری migration عوض نشده).
- دکمه‌ی منو: «⚒️ پنل OMNI» → `v13:kaveh` (callback قدیمی عمداً پایدار مانده است).

## مرزها
همه‌ی عملیات داخل همان resource boundary توکن تنانت می‌ماند: حساب از روی
`resource_account_id` همان connection خوانده می‌شود و هرگز از ورودی کاربر
گرفته نمی‌شود. سکرت‌های نود
(`AGENT_KEY`, `SECRET`) موقع آپلود به‌صورت `secret_text` ست می‌شوند و هرگز به چت تلگرام نمی‌آیند:
ربات فقط لینک اشتراک را (با protect) نشان می‌دهد.

## ادغام پنل وب کاوه

ادغام کامل پنل وب کاوه (هدلس + وب کامل) در [`docs/KAVEH-WEB-FA.md`](KAVEH-WEB-FA.md) مستند است:
معماری دوحالته (هدلس برای V13 / وب کامل برای omni-panel standalone)، پین SHA-256، موتور provision، کانال عامل با دو هدر، و چک‌لیست ادغام. برای توسعهٔ محلی پنل وب:
`cd omni-panel && npm run dev` (قرارداد JSON یکسان) و `node scripts/sync-omni-panel.mjs --rebuild` برای بازسازی باندل.
